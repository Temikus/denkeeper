## External REST API

`internal/api/` — HTTP API (enabled by default). Auth: Bearer token (API keys) or session cookies (password/OIDC). Canonical machine-readable reference: the generated OpenAPI spec (`internal/api/docs/swagger.json`, served at `GET /api/v1/openapi.json`, no auth). All paths below are under `/api/v1/` unless noted.

| Endpoints | Scope | Non-obvious semantics |
|---|---|---|
| `GET health`, `GET openapi.json`, `GET /llms.txt` | none | `llms.txt` = LLM-readable instance summary (base URL, auth notes, key endpoints, configured agents) |
| `POST chat` | `chat` | JSON or SSE streaming |
| `GET ws` | — | WebSocket upgrade; auth via `?token=` or session cookie |
| `GET models`, `GET models/details` | `agents:read` | details includes pricing info |
| `approvals` CRUD | — | `POST .../approve` accepts `?auto_approve=session\|permanent` to simultaneously create an auto-approve rule |
| `auto-approve` CRUD | `approvals:read/write` | `GET` accepts `?agent=` filter and includes TOML `config`-scoped rules (empty `id`); `POST` with `scope: "config"` → 400 |
| `schedules` (PATCH edit), `skills` (PUT edit), `kv`, `GET/PUT agents/{name}/persona/{section}` | — | plain CRUD |
| `PUT agents/{name}/identity` | `agents:write` | body `{name, emoji, theme}`; the server encodes the IDENTITY.md frontmatter (`persona.FormatIdentity`) and keeps the body (409 if the existing frontmatter does not parse) — use it rather than building YAML client-side |
| `POST agents` | `admin` | body `{name, llm_provider, llm_model, session_tier, description, create_supervisor}`; optional `create_supervisor: {name, llm_model, timeout, context_messages}` atomically creates a companion supervisor when `session_tier="supervised"`; creates persona dir, persists `[[agents]]` to TOML |
| `PATCH agents/{name}` | — | mutable: `name` (rename), `session_tier`, `llm_provider`, `llm_model`, `description`, `browser_url_allowlist`, `fallbacks`, `cost_limit_soft`, `cost_limit_hard`, `supervisor`, `supervisor_timeout`, `supervisor_context_messages`, `supervisor_decider` (+ `_mode`, `_approve_at`, `_deny_at`; validated by `config.ValidateSupervisorDecider` over the merged agent **before** any engine mutation, and a `session_tier` change is checked too — see `approval.md`) |
| `GET agents/{name}/decider-reviews` | `audit:read` | shadow decider reviews paired with the supervisor's verdict (`agent.LoadShadowReviews` → `PairShadowReviews`, shared with MCP `decider_reviews`; rule in `approval.md`); `?decider=` defaults to the agent's, `?since=` to 30d; scans at most 10k supervisor events (`truncated`); `audit:read` because rows carry tool arguments |
| `DELETE agents/{name}` | `admin` | rejects if referenced by channels/schedules or last agent; removes from TOML; does NOT delete persona files |
| `llm/providers` CRUD, `PATCH llm/config` | `admin` | create body `{name, type, api_key, base_url, organization}`; create/patch/delete update the shared live provider set (`Deps.Providers`), so agents use the change without a restart (`restart_required` when no runtime is wired); the first provider on a config with no `default_provider` becomes the default; delete 409s with `used_by` from `config.ProviderReferrers` while anything routes to it (default, fallbacks, deciders, eval judge, agent `llm_provider`/`reviewer_provider`/fallbacks); `llm/config` = global defaults; `GET llm/providers` also lists `deciders` (`name`, `provider`, `model`, `timeout`, `max_input_tokens`, `used_by` from `config.DeciderReferrers`) and marks each provider `serves_decisions` |
| `llm/deciders` CRUD, `POST llm/deciders/test` | `admin` | writes TOML, then `Deps.DeciderRuntime.Apply(snap)` rebinds supervisor stages and the eval judge live (`restart_required` without a runtime). No rename (400). DELETE 409s with `used_by` while referenced, since removal would write a config that fails to load. Validation is `config.ValidateDecider` on the snapshot before any write (includes the provider's API key). `test` is 200 for any finished call with `status` ok/error and bills no agent |
| `POST llm/providers/test` | `admin` | key check without saving: `{type, api_key, base_url, organization}` or `{name}` for a stored key, which always goes to its stored URL. **200 for every finished probe** (400/404 only for bad input) with `status` ok/rejected/unreachable/error — a 401 would read as the caller's session expiring. Never echoes the key or upstream body; refuses redirects (a key header must not follow one) |
| `auth`: `GET status`, `GET/DELETE sessions`, `POST password`, `GET oidc/test`, `POST preferences` | `admin` | password change = bcrypt verify + re-hash + persist; `oidc/test` does fresh discovery with 10s timeout; preferences = preferred login method (auto/password/apikey) |
| `GET onboarding`, `POST onboarding/dismiss\|wizard-complete\|wizard-skip` | `admin` | checklist of 5 milestones (provider = an instance with a key or ollama, not just `default_provider`); `show_onboarding` false when all done or dismissed; `wizard` block = the setup wizard's 4 steps (provider/agent/persona/chat_app) with rail details, primary agent (first agent nobody uses as supervisor), `done_count`, `restart_required` (a chat adapter is saved but not running) and `restart{available,managed}`. wizard-skip sets `wizard_completed` **and** `wizard_skipped`; wizard-complete clears `wizard_skipped` |
| `POST onboarding/chat-app/verify\|pair\|save` | `admin` | wizard chat-app step (`internal/onboarding/chatapp`). Probe answers are 200 with a `status`. `pair` long-polls ≤50s for the first private human message, skipping anything sent before the first call, and acknowledges the captured update; re-poll with `cursor` on `timeout`; 409 if that adapter already runs here or another pairing is waiting; Discord answers `manual`. `save` writes token + allowed_users + agent binding via `config.SaveChatAdapter`; 409 when `DENKEEPER_*_TOKEN` would shadow it; adapters start only on restart |
| `GET/PATCH server/config`, `POST server/reload\|restart` | `admin` | config = version, build info, CORS, WebSocket settings, in-process tool toggles + `web_fetch_max_response_chars`; reload re-reads TOML from disk, rebuilds the live provider set, and builds agents added to the file (their adapter bindings still need a restart) |
| `GET sessions/{id}/stats\|tool-calls\|skills` | `sessions:read` | per-session telemetry, tool-call records, skill usage |
| `POST sessions/{id}/clear\|compact` | `sessions:write` | both accept `?agent=` hint; compact returns `{"summary": "..."}`; see `ClearMessages` invariant |
| `POST sessions/{id}/stop` | `chat` | stops the in-flight turn **cooperatively**: `204` means "stopping", not "stopped" — the turn ends at its next step boundary, replies with a wrap-up and persists, and only a turn still running after the grace period is context-killed. Tries the `ws` key then the `api` one; `404` when neither has a turn |
| `GET telemetry/summary` | `costs:read` | `?since=&until=` filtering |
| `GET audit`, `GET audit/stats` | `audit:read` | list filters `?category=&agent=&status=&source=&search=&since=&until=&limit=&offset=&detail_max_chars=`; stats accepts `?since=` |
| `GET channels(/{name})` | `channels:read` | list: agent, adapter bindings, implicit flag, active adapter keys; detail adds `conversation_id` |
| `POST/DELETE channels/{name}/activate` | `channels:write` | body `{"adapter_key": "telegram:12345"}`; DELETE clears the override and 409s if the key is not active on this channel |
| `tools` CRUD (PUT edit), `GET {name}/health`, `POST {name}/restart\|enable\|disable` | `tools:read`/`tools:write` | enable starts the MCP process, disable stops it; both persist to TOML; 404 convention in invariants |
| `eval/task-sets` CRUD (+ `{name}/tasks` CRUD, `{name}/export|import`) | `eval:read`/`eval:write` | DELETE of a set referenced by a run → 409; import is all-or-none JSONL; `pinned_history` is replayed verbatim, never re-read from the source conversation |
| `POST eval/runs`, `GET eval/runs(/{id})`, `POST eval/runs/{id}/stop`, `GET eval/runs/{id}/summary\|samples\|pairs` | `eval:read`/`eval:write` | `sample_tasks` draws a stratified subset **server-side** and pins the ids on the run; `as_of` pins the clock; `/pairs` is the unblinded operator view and is deliberately REST-only (the judge's MCP tools must not resolve identity); `/summary` carries the gate table and verdict |
| `POST eval/runs/{id}/judge` | `eval:write` | starts the internal judge (`[eval] judge_model`) over the run's pending queue and returns `202` with the item count; `503` when no judge model is configured, `409` when the run is not terminal or a pass is already running. `eval:write` rather than `eval:read` because it spends money. It never widens the judge surface: the pass reads only `GetBlindedItem`, so the REST-only unblinded `/pairs` view stays out of reach |
| `POST eval/estimate`, `GET eval/config`, `GET eval/suggest`, `GET eval/probes` | `eval:read` (`probes` also needs `agents:read`) | estimate mirrors the run body, basis `history`/`list_price`/`unknown` and never fabricates; `config` is read-only by design (no runtime threshold writer); `suggest` is stratified across the four **history** categories (`?category=` narrows to one, which then gets the whole limit; the store applies it in SQL before the pool limit via `agent.InterestingTurnQuery.Kind`, whose CASE mirrors `eval.categoryFor` — pinned by `TestCategoryFor_AgreesWithStoreKind`; `probe` → 400), skips already-saved turns, `501` without telemetry; `probes` is the top-down counterpart — required `?agent=`, generated from tier/auto-approve/persona/skills into `category=probe`, `?set=` excludes what that set already holds, and generation stays inside the caller's scopes (403 without `agents:read`; skill family dropped without `skills:read`, approval family without `tools:read`) |
| `GET traces`, `GET traces/{id}` | `sessions:read` | L1 turn traces: list filters `?agent=&conversation_id=&source=&since=&until=&limit=&offset=`, headers only (no payload); detail carries the built system prompt, the history window as sent, the flattened tool calls with arguments/results, and what truncation dropped. **`sessions:read` deliberately, not `eval:read`** — a trace is turn content and the eval scopes are the judge's. The list repeats `capture`/`retention_days`/`max_trace_bytes` so the UI distinguishes "not recording" from "nothing yet" — echoed from a server-side snapshot (`refreshTraceSettings`, re-taken after each successful reload), never read from `deps.Config` at request time: hot reload overwrites that struct in place (`*cfg = *newCfg`) and a request-time read races it |
| `POST panic`, `POST resume`, `GET panic` | `admin` | emergency stop: cancel all in-flight requests + pause scheduler; resume clears; GET returns `{panicked, panic_time}` |

Chat streaming events (SSE and WS): `thinking`, `tool_start`, `tool_end`, `tool_approval`, `usage`, `content`, `done`. `tool_approval` carries `approval_status` plus, on `auto_approved`, a machine-readable `approval_scope` (`config`/`session`/`permanent`) alongside the human-readable text. A cancelled turn is **not** an error frame: `aborted` transitions the pending approval line, and the turn still ends with `content` (the wrap-up plus the `[engine: turn ended early — cancelled at your request]` marker) and `done`.


## Invariants

- **OpenAPI spec is a gated generated artifact**: `internal/api/docs/swagger.json` is committed (`//go:embed`-ed, served at `/api/v1/openapi.json`) and must match handler annotations. `just openapi-check` regenerates into a throwaway dir and diffs — never mutates the tree, deliberately uncached. After touching an annotated handler: `just openapi` and commit. Gotcha: `swag` only reads an annotation block **directly attached** to its handler func — a blank line or intervening declaration silently drops the endpoint from the spec.
